Demo — Intake: how work arrives

DEMO — all data is fake, for class/training only, not a real work system, do not submit anything here.

In the real system, work does not arrive from one place. It arrives from four feeds, and all four file into the Property Master. This demo shows all four, in the same order the real system uses them.

1. Live engine — new work and crew photos (FAKE)

When an order's photos arrive — a full set, or a partial set, or a completed set — they are downloaded, scanned, and QC-checked. QC-passed sets become bid evidence when a bid is needed.

Demo order (FAKE) What arrived (FAKE) Intake result (FAKE)
WO-EXAMPLE-001 Sample photo set, in progress Filed under SAMPLE-001, QC pending, state stays In Field
WO-EXAMPLE-003 Full sample Before / During / After set QC PASS, filed under SAMPLE-003, state Completed — Awaiting Owner Cross-Check
WO-EXAMPLE-004 Sample set missing the cleared-area After view QC FAIL — proof gap, filed under SAMPLE-004, state Held

Every 12 hours in the real system, a portal-native Excel report of closed orders is reconciled against the Property Master. In this demo, that step is shown as a teaching box: export → reconcile → flag differences as exceptions, never overwrite the money record from the export.

2. Email intake (FAKE)

Job notes, assigned work, and client instructions arrive by email, are parsed, and are filed to the property record and the order. Sample only:

  • Sample email: "Sample Client A — winterization scope for SAMPLE-003, approval code on file" ⇒ filed to WO-EXAMPLE-003, authority check: scope + approval code present.
  • Sample email with no scope: filed as Missing Info, not guessed. The order does not move until the missing scope is supplied.

3. Payment screenshots (FAKE)

Released payments, payment requests, and proof screenshots arrive daily in the real system. In this demo, the intake record is:

Field (FAKE) Sample value (FAKE)
Amount / date $120 sample / sample date, from the screenshot teaching card
Client / order / property Sample Client A / WO-EXAMPLE-003 / SAMPLE-003
Match result Matched to the Money ledger, or listed as "could not be matched" with the screenshot reference — never silently edited

The money record itself is never edited by intake in this demo; intake records the match and reports it. Crew-payment details are never shown here — that tab is restricted verification only in the real system, and this demo shows no payment handle at all.

4. Portal history — the past as bid intelligence (FAKE)

Historical bids, closed orders, property history, job notes, and invoices are filed as per-property dossiers. History is not an archive here — it prices future bids:

  • Approval rate by price band × client × work type (sample, from the Bids page).
  • Missed-bid analysis: a bid priced too high that was never approved, shown as a lesson, not a blame.
  • Instant-approval flag: a bid approved instantly may have been priced too low — flagged, not celebrated.

New-work detection (FAKE): a new order at an existing property, or a new property, is flagged the day it appears, filed under its property record, and shown on Live Ops and the Deadlines page — never left in an inbox.
