Standing-rule banner — read this first

Complete → report the finished state → owner cross-check → submit ONLY on the owner's word, one job at a time, never on a green light alone.

In this demo, the sequence STOPS at owner cross-check. There is no submit button, no submit form, and no action that sends anything anywhere. Any button-shaped text below is disabled text, not an action.

Submission readiness checklist (demo, same as the real system)

Before any order reaches owner cross-check in a real system, it must pass, in order: (1) photo gate — Before / During / After sets complete, flagged, datestamped by the receiving system's rule, duplicates flagged; (2) PCR match — every PCR answer matched to a photo that proves it; (3) cap check — per-property cap ledger inside limit; (4) approval code on file, in writing; (5) scope vs money, line by line. A failure at any step sends the order back to the file, never forward to submission. Ready For Office (RFO) in a real system is the owner's own step — this demo never marks RFO, and it never submits.

What a submission rejection would look like (teaching only, FAKE)

If a proof set were submitted with a missing datestamp, a bundled over-allowable line, or a missing approval code, a reviewer would reject it — not because the work was not done, but because the FILE does not prove it. The fix is always in the file first: unbundle, datestamp, get the code in writing, re-check, then owner cross-check again. See the advanced edge cases for the full rejection lessons.
