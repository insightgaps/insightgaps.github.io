How the demo is structured (features, not data)

  • Property Master spine: one property, one record, matched by ADDRESS first, never by work-order number alone. A renumbered order at the same address is the same job, not a new job plus a vanished one.
  • Live engine: new work appears in Live Ops, moves through states, and is never marked complete on a green light alone.
  • Photo QC: Before / During / After sets, flagged, datestamped by the receiving system's rule (date-only for some systems, not required for others — the demo teaches checking the rule, not assuming it).
  • Reconciliation + loss discipline: every loss carries a mandatory reason code; UNEXPLAINED is a queue driven to zero, never a closed book.
  • Submission discipline (standing rule, shown as a banner on the queue page): complete → report the finished state → owner cross-check → submit ONLY on the owner's word, one job at a time.
  • Money discipline: rates in the demo are gross = net, no discount. That is a demo teaching rule, stated here, not a real client rate.

Fake-data rule for this demo — read before using it in class

  • Work orders: WO-EXAMPLE-001 → WO-EXAMPLE-008 only. Properties: SAMPLE-001 → SAMPLE-008 only, at Sampletown / Exampleville / Demotown / Practicetown / Trainingtown addresses that do not exist.
  • Clients: Sample Client A, Sample Client B, Sample Client C only. No real client name appears in this demo.
  • Crew: Sample Lead, Sample Crew Member B/C/D only. Phones are 555-0101 → 555-0104 (fictional 555 numbers), labelled FAKE.
  • Amounts: round sample amounts ($45–$400 per demo order). Demo money totals are computed from the sample tables on the Money page and cross-check to those tables — they are NOT real totals, and they must never be quoted as real figures.
  • If you find anything in this demo that looks like it could be real, stop and report it — it is a defect, not a feature. The fake-data audit is described on the Fake seed page.
