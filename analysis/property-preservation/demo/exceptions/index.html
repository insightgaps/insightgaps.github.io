Demo — War Room: exceptions, collections, adjustments

DEMO — all data is fake, for class/training only, not a real work system, do not submit anything here.

This is the money queue the old demo was missing. It is not a report — it is work items, each with an owner, a status, a next action, and a history. Analytical flags live in a separate review lane so they never drown the actionable cash items.

Payment state machine (demo, same as the real system)

CREATED → INVOICED → (CREW_PAID | PARTIAL_CREW_PAID | CREW_NOT_REQUIRED, reason-coded) → (RECEIVED | PARTIAL_RECEIVED) → CLOSED, plus DEDUCTION_CONFIRMED and owner-approved WRITTEN_OFF. States compute from money columns only — status text is never an input.

A work order may not sit in a mismatched state silently: received-but-crew-unpaid and invoiced-but-never-received become standing exceptions the day they cross their age threshold.

Income Ratio verdicts (FAKE, sample only)

Income Ratio = Received ÷ Expected Crew Pay. Below 1.0× is a hard flag. Each service line gets Scale / Monitor / Reprice:

Expected vs Realized, side by side, everywhere: margins, cash conversion, payment days — the gap IS the story.

Adjustment queue — a recorded decision, never a quiet edit (FAKE)

Adjustment types in this demo, same as the real system: RECORD_FACT, CONFIRM_DEDUCTION, CLASSIFY_NO_CREW, INVOICE_NOW / REVERSE_PAYMENT, WRITE_OFF, DISPUTE. Each adjustment records before → after + evidence + approver, append-only. Backlog order in the demo story: deductions first, then aged unpaid, then paid-no-invoice, then received-without-crew-cost. No "dismiss": an exception closes only via a recorded adjustment.
