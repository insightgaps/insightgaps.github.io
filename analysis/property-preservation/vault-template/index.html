How to add a deck to the Class Vault

There is no upload button, because a static site has no backend. Adding a deck means adding a file, then rebuilding. That is the whole mechanism, and it is deliberate: it keeps the vault simple, and it means no slide is ever "uploaded" without a file the owner can see.

One file per deck

Create one Markdown file in the vault's slides/ folder for each deck. Copy this pattern at the top of the file, then write a short description below it:

---
layout: layouts/page.njk
title: "The deck title, as it should appear in the list"
className: "The class name"
date: 2026-01-01
slideFile: "slides-files/your-deck.pdf"
noindex: true
---

<div data-pagefind-ignore="all">

A short description of what the deck teaches, in plain words.

</div>
  • title: the deck title, exactly as it should appear in the Vault list.
  • className: the class the deck belongs to.
  • date: the deck date, as YYYY-MM-DD.
  • slideFile: the link to the slide file itself. Put the slide file (for example a PDF) in the vault's files as a plain file, and link to it here. If there is no slide file yet, link to # and say so in the description — do not invent a file.
  • noindex: true and the data-pagefind-ignore wrapper must stay on every deck file, or the deck will leak into search. Do not remove them.

Rebuild, then check

  1. Rebuild the site (npm run build).
  2. Open the deck itself and check its slide file link works.
  3. Note: the Class Vault is currently closed and shows no slide list. A deck added as a file is not listed there until the owner opens the vault.

The vault is closed — no passcode in source

There is no passcode in this site's source, and no passcode value is written in any vault file. The owner sets a passcode before opening the vault. Never reuse a real account password as a vault passcode. The gate is obscurity, not security: anyone with the direct link and the passcode can read the slides. Class slides only — never secrets, credentials, or sensitive material.
