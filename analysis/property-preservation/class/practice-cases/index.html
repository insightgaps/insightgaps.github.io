Practice Cases — Supplementary, Fake Data Only

SUPPLEMENTARY PRACTICE ONLY. Every property, order, person, amount, and outcome below is FAKE and invented for practice. These cases are NOT exam questions, NOT hiring decisions, and NOT real jobs. They are complete enough to learn from on their own: order, photos, decision, and outcome are all given, so a reader can audit the reasoning, not just read a slogan.

Use the class tools on each case first (Five Questions → Proof Test → Money Ladder → Triage Card → SBAR), write your verdict, THEN read the outcome. Reading the outcome first teaches nothing.

Practice Case P-1 — The photo that proves the wrong house (FAKE)

  • Order (FAKE): WO-EXAMPLE-101, Sample Client A, fictional rule sheet Alpha-Practice. Job: initial secure at 201 Sample Lane, Sampletown. Claimed: secure completed, fictional $100.
  • Photos (FAKE, described): Before photo shows a blue house with a red door. After photo shows a grey house with a white door, same street name in the caption, different house number visible on the door frame.
  • Other evidence (FAKE): No dated Before photo for 201 Sample Lane itself. The After photo's timestamp matches the claimed visit date, but its landmarks do not match the Before photo.
  • Verdict: HOLD — do not approve. Proof Test fails PLACE: the After photo does not prove work at this property. The timestamp passing does not rescue a place failure.
  • Next action (FAKE): Re-photograph 201 Sample Lane, Before + After, dated and labeled, owner: Sample Lead, by Sample Day 2. Update Line: "WO-EXAMPLE-101: HOLD. After photo is a different house (place). Re-photograph, Sample Lead, Sample Day 2."
  • Lesson: A clear, dated photo of the wrong house proves nothing about this house. Landmark-First Reverse Auditing catches this in seconds; thumbnail scanning misses it.

Practice Case P-2 — The bundled line that hides an over-allowable (FAKE)

  • Order (FAKE): WO-EXAMPLE-102, Sample Client B, fictional rule sheet Alpha-Practice. Job: secure + debris, claimed fictional $400 total on one line.
  • Ledger (FAKE): Line: "Secure package $400" — inside it, the packet breaks out (in the audit, not in the claim): secure $250 + debris $150. Allowable for debris in the fictional rule sheet: $100. No documented approval code for the excess.
  • Verdict: HOLD the debris excess, approve the rest only after unbundling. Audited: secure $250 (within allowance, proven) + debris $100 (allowable) = $350 audited. The $50 excess is held pending a documented approval code.
  • Next action (FAKE): Request the approval code or a corrected unbundled invoice, owner: Sample Lead, by Sample Day 2.
  • Lesson: Bundling hides over-allowable lines. Unbundle first, judge line by line: quantity × rate × allowance × authorization. Billed ≠ earned; only APPROVED becomes PAID.

Practice Case P-3 — The renumbered order at the same property (FAKE)

  • Order (FAKE): WO-EXAMPLE-103 arrives as a follow-up at 303 Sample Road, Sampletown. An earlier fictional order, WO-EXAMPLE-099, at the same property shows no payment.
  • Trap: Calling WO-EXAMPLE-099 "unpaid" on its number alone. In this practice file, the payment for the earlier work was recorded under WO-EXAMPLE-103, the follow-up order at the same property.
  • Verdict: DO NOT classify WO-EXAMPLE-099 as unpaid until the same-property chain check runs. Address is the key: match by property first, work-order number second. In the practice file, the chain check shows the earlier work's payment under the follow-up number, so the "unpaid" label was wrong.
  • Lesson (practice guidance, not an official rule): Clients often answer a submitted order with a follow-up order at the same property and pay under the new number. No "unpaid" classification is final until the same-property successor/chain check runs. This is a chain discipline, not a reason to assume every unpaid order is paid elsewhere — check, then decide.

Practice Case P-4 — The datestamp that fails the whole set (FAKE)

  • Order (FAKE): WO-EXAMPLE-104, Sample Client A. Job: grass cut, claimed fictional $60. Photos: 12 Before, 5 During, 9 After — all present, all clear, none datestamped, and the fictional receiving system requires a date-only datestamp on every photo.
  • Verdict: HOLD — do not submit as complete. The work may be done, but the proof set does not meet the receiving system's datestamp rule. Submitting it as complete would send a proof set the system will reject, and the rejection will cost more time than the datestamp pass.
  • Next action (FAKE): Date-only datestamp pass on all 26 photos, then re-check: every photo dated, every flag (Before/During/After) correct, then owner cross-check, then submit only on the owner's word.
  • Lesson (practice guidance): Datestamp and QC traps are submission traps. A complete job with an incomplete proof set is not a complete submission. Check the receiving system's rule first: date-only for some systems, not required for others — never assume one rule fits all.

How to use these cases

  • Audit cold, in writing, before reading the verdict. Score yourself on: correct verdict, correct rule, correct next action with owner and time.
  • Then write the Update Line (≤25 words) and the 4-Line SBAR for the case you got wrong. That rewrite is the learning, not the score.
  • These cases are practice only. They do not predict exam performance, and they do not set any hiring decision.
